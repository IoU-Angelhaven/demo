The implementation model / Phase 1 / Activity 1.8

Activity 1.8

Write a Problem Definition

A clear problem definition is very important for the work that follows. It should say what problem or challenge you want to solve, and for whom.

Checklist

  • Review everything you have learned so far: approval, user research, process maps, stakeholder input and comparisons with others.
  • Write a clear problem statement: who is affected, what the problem is and why it matters.
  • Make sure the statement describes the problem, not a solution or a technology.
  • Check the statement with end users, clinical staff and key stakeholders.
  • Make it specific enough to guide decisions, but not so narrow that it rules out good solutions.
  • Get approval from the project sponsor or decision-makers.
  • Use the statement as a reference during the whole project to avoid adding work that does not belong.

Do you want to download the checklists and learn how to customise them for your own organisation? Go to Create your local guide.

Methods and tools

  • “How might we…?” questions: Turn the problem into open questions that invite ideas.
  • Point of view statement: A one-sentence summary in the form “[User] needs [need] because [insight].”
  • 5 Whys: Ask “why?” again and again to find the root cause behind the surface problem.
